# 包裹码速找 · CaiNiaoParcelCodeFinder

中文 | [English](README_en.md)

一个基于 PaddleOCR Android 示例派生的本地 OCR 工具：用相机寻找指定的四位数字，命中后停留在结果画面，也支持图片与视频文字识别。**非官方项目，与阿里巴巴、菜鸟及 PaddlePaddle 无隶属、合作或背书关系。** 不连接物流账户，不查询运单，不负责核验包裹归属。

## 功能与使用

1. 等待离线模型加载完成，允许相机权限后启动相机。
2. 在目标输入框填写恰好四位 **ASCII 数字**（如 `0007`），点击“应用”。可以在启动前或运行中应用；仅修改草稿不会生效。非法输入保留原目标，空值应用或“清除”恢复普通相机 OCR。
3. 每帧 OCR 返回时读取最新生效目标，对识别文本仅做 `trim()` 后全等比较；不做子串匹配、整数转换或额外置信度筛选。首次命中自动停止后续帧，同帧所有匹配框用加粗红框、白色描边和“命中”标签突出显示。
4. 命中画面保留；修改目标不会重写旧画面。重新启动相机、新媒体结果或模型重载会清除旧命中结果。目标只在当前 ViewModel 中保存，不持久化。**图片和视频不会触发目标查找或自动停止。**

其他能力：
- 三套成对的 FP32 模型：默认 `PP-OCRv6_small`、`PP-OCRv6_tiny`、`PP-OCRv5_mobile`，各自使用匹配字典。
- App 固定 **CPU 6 线程**；保留上游 SDK 的 QNN 实验代码和依赖，但本应用不启用 NPU/GPU。
- 识别 batch 可选 1/2/4/8，新安装默认 **4**；已有保存值优先。batch 是同一帧的文本 ROI 数，不是视频帧数，越大不一定越快。
- 原始 / 半宽高 / 四分之一宽高输入，默认四分之一；直接 Bitmap、BGR 识别，不经过 JPEG 往返。
- 模型采用其明确给出的检测参数，可在折叠的检测参数面板编辑、应用四项覆盖值。切换模型恢复目标模型默认值，切换 batch 保留覆盖值。成功的模型/batch/检测参数持久化，加载失败保留旧引擎；忙碌时禁止重载。
- 视频按索引逐帧串行处理；相机忙碌时允许丢帧，不是独立的流畅预览。推理完成后等待绘制再继续；相机请求 1920×1080，实际尺寸由设备决定，后台/生命周期变化会停止相机。
- 显示实际处理尺寸、前处理 / Det / Rec / 后处理和累计 FPS。前处理不含图片/视频解码；后处理到 Compose 首次绘制完成，不等于屏幕物理显示延迟。

## 安全与隐私

- 模型随 APK 打包，正常 OCR 无需联网。当前源清单不声明 `INTERNET` 权限，没有上传图片的业务流程；首次构建下载依赖和模型需要网络。
- **启动时会尝试识别最新可访问的相册图片**，并非只读取用户手动选择的文件。为此会请求相册读取权限：Android 13+ 为 `READ_MEDIA_IMAGES`，旧版本为 `READ_EXTERNAL_STORAGE`；Android 14+ 同时声明/请求选择照片访问。当前自动识别逻辑仍检查完整图片读取授权，只有部分授权时不能保证自动识别可用，可改用系统媒体选择器手动选择图片/视频。
- 相机权限仅用于相机功能，拒绝后仍可使用手动媒体选择。当前 `allowBackup=true`，系统备份可能包含应用偏好；本项目没有另加端到端加密或禁用系统备份。
- OCR 会误识别、漏检；四位号码并非唯一身份凭证。取件前核对完整信息，不要仅凭命中提示拿取包裹，也请避免拍摄/传播他人的姓名、地址和电话。

## 开发与构建

独立目录包含 `app` 和 `ppocr-sdk`，无需父级 PaddleOCR 仓库。使用 **JDK 21**（当前验证环境），Gradle Wrapper **8.9**、AGP **8.7.3**、Kotlin **2.1.0**；Java/Kotlin 编译目标仍为 17。安装 Android SDK Platform **35** 及 Build Tools **34.0.0**（AGP 默认）；应用最低 Android 8.0/API 26，target 35，仅打包 `arm64-v8a`。

1. 配置 `JAVA_HOME` 为本机 JDK，配置 `ANDROID_HOME`，或创建不入库的 `local.properties`，例如 `sdk.dir=/path/to/Android/Sdk`（Windows 可使用 `C:/Android/Sdk`）。不要提交机器路径和密钥。
2. 准备 Python 3，然后在项目根目录运行：
   ```sh
   python scripts/provision_models.py
   ```
   默认缓存为项目内 `.model-cache/`。脚本从官方地址下载并校验 SHA256，恢复六个 ONNX 及六个 YAML（包含识别字典）。模型不入 Git，但构建 APK 前必须备齐。详见 [模型说明](scripts/MODELS.md)。
3. 构建并检查：
   ```sh
   ./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
   ```
   Windows cmd 使用 `gradlew.bat` 替代 `./gradlew`。输出为 `app/build/outputs/apk/debug/app-debug.apk`。首次构建需要访问 Gradle/Maven 仓库（配置保留了阿里云镜像及官方仓库）。构建不会自动安装手机。

**应用 ID/命名空间刻意保持 `com.paddle.ocr.demo`**，避免迁移已有设置与数据；桌面名称为“包裹码速找”。因此不能与原 Demo 同包并存；覆盖安装要求签名一致，不同机器的 debug 签名可能不同。不要为解决签名冲突贸然卸载而丢失数据。

单元测试和 lint 不等于真机验收；原生烟测需显式连接设备并运行。新目录仍需人工确认相机权限、目标命中、后台恢复、各模型准确率和持续运行表现。发布签名、应用商店合规及品牌/素材授权需自行审核。
